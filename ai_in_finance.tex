% Measured-box floats (2026-10-13). Every figure and table in the book is set in
% one of these two environments, so its caption is never wider than the
% picture or table (but at least 0.65\linewidth), and table captions sit below:
%
%   \begin{bookfigure}[<options>][<short caption>]{<caption>}{<label>}
%     <tikzpicture or \includegraphics>
%   \end{bookfigure}
%
%   \begin{booktable}[<options>][<short caption>]{<caption>}{<label>}
%     <tabular>
%   \end{booktable}
%
% <options> is the float placement (htbp, htb, ...), optionally followed by
% captionskip=<length>, floatrow's object-to-caption gap for that one float
% (default 10pt; \setlength{\abovecaptionskip} does nothing under floatrow).
% The short caption is optional and goes to the List of Figures/Tables. The
% body is set in an lrbox, so it is not captured as an argument: verbatim and
% \index work in it as anywhere else.
%
% Tables use \floatbox[\capbot]{table}, never \ttabbox: floatrow.sty defines
% \newfloatcommand{ttabbox}{table}[\captop][\FBwidth], baking \captop into the
% command, so \ttabbox always puts the caption on top and no
% \floatsetup{capposition=bottom} can override it.
%
% The float is opened with \figure/\table rather than \begin{figure} so that
% \end{bookfigure} handles the space after it exactly as \end{figure} did. The
% spaces inside the \ffigbox/\floatbox arguments reproduce the line breaks of
% the hand-written idiom this replaced, so the output is identical to it.
\ExplSyntaxOn
\clist_new:N \l__bookfloat_place_clist
\tl_new:N \l__bookfloat_setup_tl
\keys_define:nn { bookfloat }
  {
    captionskip .code:n =
      \tl_put_right:Nn \l__bookfloat_setup_tl { \floatsetup { captionskip = #1 } }
  }
\cs_new_protected:Npn \bookfloatbegin #1#2
  {
    \tl_clear:N \l__bookfloat_setup_tl
    \keys_set_known:nnN { bookfloat } {#2} \l__bookfloat_place_clist
    \use:x
      {
        \exp_not:c {#1}
        \clist_if_empty:NF \l__bookfloat_place_clist
          { [ \clist_use:Nn \l__bookfloat_place_clist { , } ] }
      }
    \centering
    \begin{lrbox}{\bookmeasuredbox}
  }
\cs_new_protected:Npn \bookfloatsetup { \tl_use:N \l__bookfloat_setup_tl }
\ExplSyntaxOff

\chapter*{Preface}
\markboth{PREFACE}{PREFACE}

Artificial intelligence is now embedded in nearly every corner of the financial industry: credit decisions, fraud alerts, 
trade execution, risk limits, portfolio construction, and increasingly the generative tools analysts use to read a filing 
or draft a note. The people building and overseeing these systems are disproportionately trained in mathematics, statistics,
 physics, computer science, and engineering, not finance. They can derive a gradient, debug a training loop, and reason 
 about a covariance matrix without much trouble. What they often lack, at least at first, is the financial vocabulary and 
 institutional context that turns a model into something a bank, a fund, or a regulator can actually use, and use 
 responsibly. This book is written to close that gap.

\section*{Who This Book Is For}

I have written this book for readers who are already comfortable with quantitative reasoning and, ideally, with basic 
Python, but who have limited exposure to finance and economics: graduate students and advanced undergraduates in 
engineering, the physical sciences, statistics, and computer science; practicing data scientists and machine learning 
engineers moving into a financial role; and anyone building a career on the specific combination of skills this book 
covers. No prior finance coursework is assumed. Chapter~\chnum{markets} introduces financial markets and institutions from first 
principles, and every subsequent chapter builds forward from there, so a reader with no finance background at all should be able to start at Chapter~\chnum{intro} and never feel lost.

\section*{How This Book Is Organized}

The twenty-one chapters are ordered by dependency, not by alphabetical convenience or topical grouping. Chapter~\chnum{python} teaches 
the Python tools, NumPy, pandas, scikit-learn, matplotlib, that nearly every later chapter's worked examples rely on. 
Chapter~\chnum{markets}'s markets and institutions precede Chapter~\chnum{statements}'s financial statements, and Chapter~\chnum{statements}'s statements feed directly 
into Chapter~\chnum{valuation}'s valuation and asset-pricing models, which in turn recur throughout the risk, portfolio, and credit 
chapters that follow. The four risk chapters themselves run as a deliberate sequence: market risk (Chapter~\chnum{marketrisk}) models 
how much a position's value can move, credit risk (Chapter~\chnum{creditrisk}) whether a counterparty will pay at all, and operational 
risk (Chapter~\chnum{oprisk}) the losses that remain when the institution's own processes, people, or systems fail, each defined by 
exactly what the one before it leaves out; insurance (Chapter~\chnum{insurance}) then closes the sequence from the other side of the 
table, the industry whose entire product is bearing those risks for a price, and whose actuarial machinery the 
operational-risk chapter has already borrowed. Machine learning fundamentals (Chapter~\chnum{ml}) are introduced once, in depth, 
and then reused, not re-taught, in every later chapter that needs a regression, a classifier, or a neural network: 
fraud scoring, credit scoring, algorithmic trading signals, natural language processing, and the explainability methods 
of Chapter~\chnum{xai} all build on that same foundation rather than each inventing their own. Chapter~\chnum{rl} closes the methods 
sequence proper with reinforcement learning, built on the trading and portfolio machinery of Chapters~\chnum{portfolio} through~\chnum{hft};

Beneath this chapter-by-chapter dependency, the book falls into three broader parts, marked as such in the Contents. Part I, Foundations (Chapters~\chnum{intro} through~\chnum{timeseries}), is preparation: the finance vocabulary, institutions, financial statements, and valuation machinery a reader needs before any model can be usefully applied, together with the Python and machine learning fundamentals every later chapter draws on. Part II, Applications (Chapters~\chnum{marketrisk} through~\chnum{altdata}), covers the applications a working quantitative finance professional encounters most often: market, credit, operational, and insurance risk, portfolio construction, algorithmic and high-frequency trading, fraud detection, and the natural language processing and alternative-data methods reshaping how firms extract signal from unstructured sources. Part III, Advanced Topics (Chapters~\chnum{xai} through~\chnum{capstone}), turns to more advanced and specialized territory: explainability, fairness, and regulation; reinforcement learning; agent-based models of markets and financial networks; and a closing capstone that applies the entire toolkit to one real, publicly available dataset end to end. A reader pressed for time could stop after Part II and still have a working, practitioner-level command of AI in finance; Part III is where the book pushes into territory still actively being worked out in research and in practice.

Every chapter follows the same shape: an introduction, several sections of exposition built around at least one fully worked numerical example a reader can check by hand, a discussion of the practical challenges and limitations specific to that chapter's topic, and a closing sequence of Key Takeaways, Suggested Exercises, and Further Reading pointing to the standard textbooks and original papers behind the chapter's material. Most chapters' Suggested Exercises close with a challenge question that asks the reader to redo one of the chapter's own methods on a real, freely obtainable dataset, from sources such as the UCI Machine Learning Repository, Kaggle, SEC EDGAR and the SEC's enforcement releases, or the Consumer Financial Protection Bureau's HMDA and consumer-complaint databases, or, in the handful of cases where no clean real dataset exists (a limit order book fast enough to show latency arbitrage, say), on data generated by a documented simulation instead; the point of each is to show what a real-world version of the chapter's toy example actually looks like, messy edges included.

Each chapter is sized for a single 90-minute class session, though the chapters are not all the same length. Chapters~\chnum{marketrisk}, \chnum{creditrisk}, \chnum{portfolio}, \chnum{fraud}, \chnum{nlp}, and \chnum{rl} carry noticeably more worked material than the rest, each running roughly a fifth longer than a typical chapter, Chapter~\chnum{nlp} most of all, its generative-AI coverage being deliberately deeper than that of any other single topic here. An instructor who works through every worked example in those six should plan two sessions for each, or else select among their later sections. Chapter~\chnum{oprisk} is the deliberate opposite, shorter than the rest by design, and Chapter~\chnum{insurance} is also on the short side; both leave room within a single session for exercises, discussion, or an early start on the chapter that follows. The book is designed as the backbone of a one-semester course meeting twice a week: at roughly one chapter per session, the twenty-one chapters fit into such a semester with room left over for review, examinations, and project presentations. Giving all six longer chapters a second session, about twenty-seven sessions in all, would use up most of that room, so most instructors will double only the two or three that matter most to their course. An instructor pressed for sessions can also be selective, most naturally among the more specialized chapters (\chnum{oprisk}, \chnum{insurance}, \chnum{hft}, \chnum{fraud}, \chnum{altdata}, \chnum{rl}, and~\chnum{abm}), without breaking the dependency chain described above. A course meeting once a week can work from a core of about fourteen chapters, Chapters~\chnum{intro} through~\chnum{creditrisk}, then \chnum{portfolio}, \chnum{algotrading}, \chnum{nlp}, \chnum{xai}, and \chnum{capstone}, with the rest assigned as independent reading or term-project material. And the book serves a reader working through it independently at their own pace exactly as well. Three appendices follow the twenty-one chapters: a catalog of real financial datasets and APIs for readers who want to extend the book's examples with real data of their own, a glossary of finance and trading terms for readers who hit an unfamiliar term before the chapter that formally introduces it, and a career map connecting the industry's actual quantitative roles to the chapters that prepare for each, for the reader this book was written for in the first place.

Real, named case studies are woven throughout rather than confined to a single chapter: the insurer insolvencies after Hurricane Andrew in 1992 that created the catastrophe-modeling industry, the 1998 collapse of Long-Term Capital Management, the 2008 financial crisis and the Gaussian copula's role in mispricing CDO risk, the 2008 Soci\'et\'e G\'en\'erale rogue-trading loss, the 2010 Flash Crash, the 2012 Knight Capital trading malfunction, the 2012 JPMorgan ``London Whale'' loss, the Danske Bank Estonia money-laundering scandal, the 2019 Apple Card gender-bias controversy, and the SEC's 2022 settlement with Schwab over undisclosed robo-advisor cash allocations, among others. These are real events with real consequences, included because the lesson a formula teaches in the abstract is rarely the lesson a genuine failure teaches in practice. Chapter~\chnum{capstone}'s capstone case study goes further still, working a real, publicly available consumer-credit dataset end to end, undocumented category codes, class imbalance, model comparison, calibration, explainability, and fairness auditing included, using nothing invented for the occasion.

\section*{What Makes This Book Different}

Five features shape this book more than any other, and a reader deciding whether it suits them should know them in advance. First, it teaches finance from first principles to readers who are already quantitatively trained: no finance background is assumed, but comfort with quantitative reasoning and basic Python is, so the finance is explained in full while the mathematics and machine learning are allowed to move at the pace such a reader expects. Second, every number in the text is reproduced by an executed companion notebook, and that reproduction is checked automatically: the repository pins the library versions that produced the published outputs (\texttt{requirements.txt}) and includes a script (\texttt{tools/check\_notebooks.py}) that re-executes the notebooks and reports any output that has drifted from what the book quotes. Third, each method is taught through at least one worked example small enough to check by hand, so a reader can see exactly what a model computes before trusting it at scale. Fourth, risk and regulation receive sustained depth rather than a closing chapter: four chapters on market, credit, operational, and insurance risk, and a full chapter on explainability, fairness, and the regulation of models, reflecting how much of the industry's actual work with AI is governed by them. Fifth, Appendix~\apnum{careers} maps the industry's quantitative roles to the chapters that prepare for each, so a reader building a career can see which parts of the book matter most for the job they want.

\section*{What This Book Does Not Cover}

A book this broad still has to stop somewhere, and a few neighboring subjects are deliberately left to other texts. Trading strategies for cryptocurrencies and digital assets are not covered; the market-microstructure and trading chapters apply to any electronic market, and on-chain data appears in Chapter~\chnum{altdata} as one alternative-data source among many, but crypto-specific venues, instruments, and strategies are left to specialist sources. Stochastic calculus and derivatives theory beyond the binomial model and Black-Scholes-Merton are not developed here; a reader who needs Itô calculus, exotic options, or term-structure models should turn to a standard derivatives text such as Hull's \emph{Options, Futures, and Other Derivatives} and, beyond it, a text on stochastic calculus for finance. Quantum computing and its prospective financial applications are not discussed. Corporate finance, including capital structure, mergers and acquisitions, and deal valuation, appears only as far as Chapters~\chnum{statements} and~\chnum{valuation} need it; a corporate finance text such as Brealey, Myers, Allen, and Edmans covers it properly. And accounting standards are introduced only to the depth needed to read financial statements and the expected-credit-loss rules; a reader who needs IFRS or US GAAP in detail should consult an intermediate accounting text or the standards themselves.

\section*{Technical Notes}

A few of the formulas used in this book are quoted without a full derivation, since working through every one of them line by line in the main text would bury the finance and the intuition, which is this book's actual subject, under mathematics that is not. Where a derivation is long enough to be worth doing properly but not essential to following the chapter that uses the result, I have written it up separately as a standalone technical note and placed it in the \texttt{technical notes} folder of the same GitHub repository as the companion notebooks, linked above.

These notes are entirely optional. They exist for the reader who wonders where a particular formula actually comes from and wants to see the argument worked out in full; skipping them has no effect on understanding any of the approaches covered in this book, since every chapter states the results it needs and shows how to use them regardless of whether the underlying derivation has been read. More notes will be added over time as new formulas in the book warrant one.
